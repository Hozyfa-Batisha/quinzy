# 🛠️ Quinzy - Technical Documentation

This document explains the technical architecture, data flow, and components of Quinzy, a student self-assessment learning tool.

---

## 1. Architecture Overview
The project is built as a **Vanilla JavaScript Single Page Application (SPA)**. It does not require a traditional backend server or database during runtime. 

* **Frontend:** HTML5, Vanilla CSS3 (with CSS Variables), and Vanilla JavaScript (ES6+).
* **Content Management:** Markdown files (`.md`).
* **Build System:** A custom Node.js script parses the Markdown files and generates a JSON-like JavaScript object (`lessons.js`) which the frontend consumes.

## 3. The Content Pipeline (Markdown to UI)

To make content authoring easy for teachers/writers, the platform uses Markdown. However, browsers cannot query Markdown files efficiently without a server. 

### The Build Step
Whenever a Markdown file is edited in the `Sources/` directory, the developer runs:
```bash
npm run build
```

**What `scripts/build-content.mjs` does:**
1. It reads `lessons.config.json` to get the list of active lessons and their metadata (titles, descriptions, order).
2. It fetches the corresponding `-summary.md` and `-questions.md` files from the `Sources/` directory.
3. It converts the Markdown summary into raw HTML using custom regex parsing.
4. It parses the `-questions.md` file, identifying question types (`MCQ`, `True/False`, `Matching`, `Open`) based on specific markdown formatting conventions (like `**س1:**` and `**الإجابة الصحيحة:**`).
5. It compiles everything into a massive JavaScript array of objects and outputs it to `assets/js/data/lessons.js` as `window.LESSON_DATA = [...]`.

When `index.html` loads, it imports `lessons.js` globally, making all content instantly available to the frontend without any API calls.

## 4. Frontend Modules & State Management

The app avoids frameworks like React or Vue, relying instead on a modular Vanilla JS pattern. State is managed in memory, and views are toggled using the CSS `.hidden` class.

* **`App` (main.js):** The central controller. It reads `window.LESSON_DATA`, initializes the views, and binds global click events.
* **`ThemeManager` (main.js):** Handles the Light/Dark mode logic. It reads the user's OS preference (`prefers-color-scheme`), persists the user's choice in `localStorage`, and toggles the `data-theme="dark"` attribute on the `<html>` tag.
* **`HomeView` (home.js):** Loops through the data and dynamically injects the HTML for the lesson cards in the grid.
* **`LessonView` (lesson.js):** When a user clicks a lesson, this module hides the home section, shows the lesson viewer, injects the HTML summary, and initializes the QuizEngine.
* **`QuizEngine` (quiz.js):** Tracks the current question index, the user's selected answers, and calculates the score. It handles the logic for different question types (e.g., verifying if the selected dropdown matches the `correctMap` for matching questions).
* **`ResultsView` (results.js):** Displays the final animated modal, calculating percentages and breaking down the score into correct/wrong/open-ended metrics.

## 5. Styling Architecture & Theming

The CSS is heavily componentized to keep specificity low and maintainability high.

### CSS Variables & Dark Mode
All colors, shadows, and transitions are defined in `:root` inside `variables.css`. 
Dark mode is achieved simply by redefining those exact same variables under the `[data-theme="dark"]` selector.

```css
:root {
  --color-bg: #f0f4ff;
  --color-primary: #4f46e5;
}

[data-theme="dark"] {
  --color-bg: #0b0f1e;
  --color-primary: #818cf8;
}
```

### Animations
Custom CSS keyframe animations (like `fadeIn`, `fadeInScale`, `float`) are defined in `base.css` and applied across components to give the app a modern, dynamic feel. For instance, the lesson cards use staggered animation delays (`animation-delay: 0.07s`) calculated via JavaScript in `home.js` to create a cascading entrance effect.

## 6. Supported Question Types
The custom Markdown parser supports four distinct question structures:

1. **Multiple Choice (MCQ):** Standard 4-option questions with a single correct key.
2. **True / False:** Renders as two large, selectable buttons.
3. **Matching:** Renders as a grid with dropdown selects to pair concepts together.
4. **Open-Ended / Analytical:** Renders a large `textarea`. When submitted, the system displays a "Model Answer" (Model Answer) for self-evaluation.

---

## 7. How to Add a New Lesson
1. Create a new folder in `Sources/Done/` (e.g., `Sources/Done/Cyber Security/`).
2. Create two markdown files: `cyber-summary.md` and `cyber-questions.md`.
3. Open `lessons.config.json` and add a new entry pointing to these files.
4. Run `npm run build`.
5. Run `npm run serve` to test your new lesson in the browser!
